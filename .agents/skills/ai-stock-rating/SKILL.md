# AI 股票质量评级

目标：从广泛的 AI 关联池中选出值得优先研究的公司。先复用已有行业、官方业务证据及结构化财务，批量划分研究优先级；再对重点公司做质量核查。初评和已核查评级分别展示，估值、买入时点与未来收益概率分别处理。

项目位于 `/Users/admin/Code/stock`，页面位于 `analysis/ai_value_chain_map_v1/`。执行前读项目 AGENTS.md 和 [评级协议](references/protocol.md)。规则版本为 `ai_quality_v1`；修改评级定义须另升版本，保留旧快照。

## 低成本批量初评

用户要求扩大覆盖、减少逐股搜索时，先读 [批量初评协议](references/screen_protocol.md)，运行独立的 `ai_research_screen_v1`。默认分母为现有 AI 关联池，不把全池行业覆盖冒充 AI 评级覆盖。用户要求80%时，458只股票至少需367只获得有依据的等级；不为凑覆盖率捏造业务。

```bash
python3 analysis/ai_value_chain_map_v1/quality/screen.py --as-of YYYY-MM-DD
python3 analysis/ai_value_chain_map_v1/build.py
```

复用已有逐公司官方业务标签与财务缓存，不逐个重新搜索。每只股票至少展示行业、价值链环节、具体业务依据、初评等级、核查状态和下一步动作。行业本身只能支持分类；AI业务等级还须有具体业务证据。跨群分布统计股票数量，不能编造公司AI收入占比。

若刚更新成员采集或业务标签，先运行一次 `build.py` 刷新 `data.json` 输入，再运行初评脚本和最终构建。构建器会检测成员、业务、财务及核查资料的语义变化，让旧初评失效；仍可生成新股票池，不会被旧初评阻塞。

初评的A/A−/B用于安排研究顺序；未逐股核查的初评最高为A。A+只继承有效的已核查评级。财务缺失或风险未核查在详情中明确，不能把“初评A”称为已核查的优质公司。保留 `quality/current.json` 和旧核查快照；初评独立保存 `screen_current.json`、CSV及不可覆盖快照。

把付费研究集中在持仓／自选、高价值链路、少量补证即可完成核查及重要资料变化的公司。批量脚本能解决的分类、计数、财务计算和筛选不用模型重复处理。

## 执行一次逐股核查评级

1. 确定评级截止日与股票池快照。默认当前已知池；需要刷新成员时用页面目录的 `capture.py`，在可终止子进程内限制35秒。基金身份与成员业务日期分开，未展开成员不臆造。先查看 main 分支与未提交工作，所有输出限定本次目录。
2. 准备资料。优先复用来源可追溯的近期 SEC 公司事实、财报及发行人资料；补读最新官方业绩、AI 业务规模、竞争位置及风险。行情不参与质量等级，通常无需下载行情。需要行情时遵守 Local→R2→OpenD；不自动上传 R2。
3. 按协议填写业务重要性、商业兑现、竞争优势和发展阶段。给每项判断附实际查阅的官方资料、披露日期、查阅日期和简短依据。公司官网提到 AI、行业名称或价格相关系数不能单独支持 A/A+。未知保持 null。若公司名/代码/市场不匹配，先核实身份。
4. 运行确定性财务提取和评级程序。以下命令先读现有资料，不自行代替逐股研究；新业务证据写在 `quality/reviews_*.json` 后重跑：

   ```bash
   python3 analysis/ai_value_chain_map_v1/quality/prepare_financials.py --as-of YYYY-MM-DD
   python3 analysis/ai_value_chain_map_v1/quality/rate.py --as-of YYYY-MM-DD --final
   python3 analysis/ai_value_chain_map_v1/build.py
   ```

5. 检查所有输入股票有输出，未知、未入围、资料过期均单列。检查 A+ 和 A 的商业/财务证据，复算关键财务值；输出本次等级、理由、缺项、复评条件以及相对上次的新增/升级/降级/退出/转待评级。首次运行标“首次评级”，不能制造历史变化。资料提取日期不是资料下载日期；使用已有缓存时仍须确认披露期间、来源取得时间与截止日，过期资料不能通过重跑程序获得新的有效期。
6. 更新单文件 HTML：默认只看有效的 A+ / A；提供全部等级、A−、B、待评级和资料过期筛选，支持原有池/产业/搜索组合。详情展示财务期间、资料取得时间、业务证据、评级依据、下次复评触发条件。验证桌面/手机、组合筛选、导出与数据一致性。

交付 `quality/current.json`、带 run_id 的不可覆盖历史快照、CSV 及更新后的 HTML。说明评级数量、未完成范围、数据截止和限制；不要将分析规则说成经过收益验证的策略。

## 动态选择与复评

每次运行重新评价当前成员，不永久冻结一份 A+ 名单。优先复评新财报、AI 收入/订单兑现、客户流失/集中度变化、竞争替代、产能/资本开支、债务融资、股权稀释和业务身份变化。默认有效期30日；重要事件可提前使评级失效。旧评级留在历史中，资料不足时可转待评级，不能沿用成当前评级。

用户可输入：`使用 $ai-stock-rating 重新评级并更新网页`。默认先重跑批量初评，再只核查关键变化和高优先级缺项；需要全面逐股核查时明确说明。本 skill 是手动可重复工作流；只有用户要求定时执行时才创建自动化。网页打开不会自行联网评级。券商分组同步与下单均不在默认动作中。

## 成本和边界

行业初筛及结构化财务由本地脚本处理，付费研究优先用于有望入围和资料变化的公司。用户授权委派时，可沿用其 agyd / Codex 6 Luna 偏好；agyd 反复读取、无有效输出时停止并明确报告，不将失败当作完成。无须把每次运行扩大成全量网页重复查询。

缺关键资料不降成 B；B 表示已核查的外围路径或已证实严重业务/财务弱点。不得按股价暴涨、事后表现或旧模型概率选评级。保留原业务关联等级，A+ 不等同买入资格；未使用统一估值资料时估值显示“未评估”。

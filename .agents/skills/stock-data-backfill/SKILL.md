# 股票基础数据补齐

维护事实数据时间线，输出供报表层读取的不可变数据快照与覆盖清单。执行本 skill 不计算股票标签，不改变质量评级，不下单，不自动上传 R2，也不自行安装定时任务。

## 两层流程与默认频率

- 行情按相应市场交易日、收盘且数据完整后补齐；新闻每天增量检查，公告和财务随新披露补齐。实际时区、运行时间和重试预算由任务参数确定。
- 数据粒度、补齐间隔、标签刷新间隔、标签计算窗口分别配置。当前五标签需要日收盘数据；60 分钟下载器不等于日线下载器。
- 首次准备当前五标签至少需要 141 个连续有效收盘。若要补算最近 60 日历天的标签曲线，还需从最早评估日向前准备相应预热历史；用官方交易日历推算，不写死一个自然日起点。
- 股票池默认是用户当前自选；显式证券清单或已有报告成员范围优先。记录成员快照时间，不自行扩展到 ETF 成分、账户资产或全市场。

## 执行一次补齐

1. 固定本次 `requested_cutoff`、股票池、数据源/粒度、历史需求和总预算。支持初始化、增量、修复三种任务；先输出缺失计划，避免不必要的全池全历史下载。
2. 查询实际自选分组名称再读取成员。特别关注当前名称为“特别关注”，不能假定 `Favorites` 有效。按市场代码保留证券身份，发行人用于财报/新闻去重；ETF、杠杆/反向产品、非证券及未知身份分别记录。
3. 检查本地有效数据的完整范围、截止和内部缺口，再检查相同粒度、市场、价格口径的 R2 归档，最后才请求 OpenD。命中文件路径不等于覆盖合格；R2 返回成功不等于数据最新。跨年逐年处理。
4. 行情补缺按官方交易日历区分休市、半日市、停牌和真缺失。日线收盘未完成时不作为完整观察；分钟数据如被要求则保留约定的全日时段，不把常规盘与扩展时段混为同一序列。OHLC 有效性、成交量异常和覆盖状态分别检查，零成交量不单独作为删证券依据。
5. 使用单一、明确的复权/币种/时段口径。不能直接把不同来源复权价格拼接；公司行动导致前复权历史变化时重新取得一致序列并另存版本，保留旧版本及修订关联。不得以新增数据覆写冻结实验的原始输入。
6. 新闻及披露按发行人增量采集，保留来源 URL、发布时间、真实首次取得时间、内容哈希、报告期间与修订关系。使用重叠回查处理晚到数据，不能只按最大发布时间游标跳过迟到新闻。去重后仍保留不同来源的证据关联。官方披露优先；传闻保留来源类型，不改写为确认事实。
7. 先写临时文件、校验，再原子发布新的不可变快照和清单。失败不替换已有完整版本。保存已完成证券，返回未完成、超时、权限不足及不可用原因。按交接契约发布本次清单；`current` 只指向最近已发布清单，不代表全部数据合格。

## 耗时、停止条件与调度

网络请求设置单次超时、总截止和有限重试；OpenD 用可终止工作进程防握手卡死，先执行 `ft.SysConfig.enable_proto_encrypt(False)`。串行或按供应方限速获取，不能用盲目并发绕过配额。预算到达后停止发起请求，保留已验证文件和明确的剩余任务。

同一数据任务防重入。重跑同一范围应复用未变内容，不能制造新证据时间。电脑睡眠/退出导致未执行时保留缺口；恢复后可补事实，但不能补造当时已经运行的评估记录。云端 OpenD 地址必须可配置，不能假定云端的 `127.0.0.1` 是用户 Mac。

每次记录总/分阶段耗时、各源请求/重试次数、字节数、缓存命中、新增/修订/缺失数量及实际发生的供应方费用。未知费用写未知，不推算成零。R2 使用既有配置，日志不显示凭证；新原始行情不入 Git，不自动 push R2。

## 完成与验收

交付清单路径、`data_run_id`、成员与数据截至时间、变化集、覆盖统计、失败原因和资源消耗。按源区分“取得新证据”“内容未变”“沿用旧缓存”“源不可用”，不能把每日检查说成每日财报更新。

适配器实现至少验证：内部缺失且首尾齐全仍能发现；休市不误报缺行情；过期 R2 命中继续尝试兜底；预算中断保留完整旧文件；修订产生新版本；重复补齐内容幂等；旧实验输入哈希不变；输出无未来数据、原始数据/凭证未误入 Git。可用本地 fixture 验证失败路径，另报告真实获取证据，不能互相替代。

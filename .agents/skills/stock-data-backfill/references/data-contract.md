# 数据层与报表层交接契约 v1

这是两个 skill 的接入目标，不表示仓库已有对应自动化程序。首次实现时固定契约版本；已有等价结构可以适配，字段语义不能静默改变。

## 存储与身份

- 推荐新原始行情位置：`market_data/stock_data_v1/captures/<capture_id>/daily/<market.symbol>.parquet`。Parquet 使用 ZSTD level 7；已发布 capture 不覆写。旧研究数据只读复用，变更另存 capture。
- 新闻/披露原文、取得账本及数据清单放在已忽略的 `.cache/stock_data_v1/`，或经确认等价的忽略目录。推荐清单路径 `runs/<data_run_id>/manifest.json`，`current.json` 为原子更新的指针。原始材料和凭证不复制到可提交报表中。
- 每个输入引用包含稳定的 `dataset_id`、相对仓库路径、SHA-256 和 capture/version。仅保存日后会被覆写的文件路径不足以复算。人工 R2 归档后仍保留口径和版本关联。
- `security_id` 包含市场和证券代码，`issuer_id` 用于业务资料复用；例如两类股不能合并价格序列。身份、成员和来源均可为未知，不猜测发行人。

## 时间含义

| 字段 | 语义 |
| --- | --- |
| `requested_cutoff` | 本次希望评估的信息截止时点，含时区 |
| `event_time` / `bar_start` / `bar_end` | 事实发生或行情统计区间；不能把 K 线时间字段直接假定为结束时间 |
| `published_at` | 来源公布时间；财务 `period_end` 不能代替它 |
| `available_at` | 能核实的供应方可获取时间；未知为 null |
| `received_at` | 本系统真实首次取得该版本的时间；重读缓存不能刷新它 |
| `checked_at` | 本次检查来源的时间；内容未变也可更新此时间 |
| `complete_through` | 此粒度/口径的连续完整数据截止，不只是最后一条时间 |
| `observation_mode` | `live` 或 `historical_reconstruction` |

价格时间使用交易所时区并保存 UTC 时间；收盘标签依官方 session 标识和市场日历。一天中 US/HK/JP 完整行情截止可能不同，逐源记录，不能仅靠一个页面日期掩盖差异。完成交易日是行情目标；新闻在周末仍可有新事实。

收盘行情截止与信息截止独立：例如 16:00 的行情在 16:10 才取得，16:15 的评估可使用它，但不能冒充 16:00 已知。默认每日任务在数据就绪后固定信息截止，再选择此前最新完整 session；若用户明确要求收盘瞬间的评估，按当时真实可用输入处理迟到行情。

实时结果只能使用评估截止前实际取得的输入版本。历史补算须说明供应方可用时间/历史复权的假设；不能把后来取得、后来修订的材料伪装为过去已知。无法确定精确披露时刻时保留时间精度/未知状态，不据此生成盘中已知结论。

## 数据清单最小字段

| 字段 | 内容 |
| --- | --- |
| `schema_version`, `data_run_id` | `stock_data_manifest_v1` 和唯一运行标识 |
| `observation_mode`, `requested_cutoff` | 本次模式与目标时点 |
| `started_at`, `finished_at`, `status` | 运行时间；`complete` / `partial` / `failed` |
| `universe` | 成员快照引用/哈希、`observed_at`、来源、身份分类及查询失败；不能硬编码证券数量 |
| `requirements` | 按源的粒度、市场、日历/时段、币种/复权、所需范围；标签预热需求由报表层提供 |
| `datasets` | 逐证券/发行人/数据源的版本引用、请求及实际范围、时间字段、完整性、缺失区间与异常 |
| `changes` | 新增/修订 dataset ID、受影响身份与事件时间范围、旧新哈希关联 |
| `resources` | 阶段耗时、请求/重试次数、字节数、缓存命中及已知费用 |
| `errors` | 配置、权限、网络、超时、日历缺失、源未接入等可定位原因 |

`datasets` 中另保存独立的覆盖/新鲜度状态，例如 `complete`、`short_history`、`missing_intervals`、`stale`、`unavailable`、`unsupported`、`not_requested`。明确哪些源是必需、哪些只是辅助：辅助源未接入时可返回部分交付，但不能据此声称综合信息完整。已检查却无新增新闻，与根本没有新闻渠道，是不同状态。

缺失值用 null 和原因；未知不等于零。停牌、上市前无历史、真实零成交量与接口错误不能混成一个状态。

## 报表层怎样消费

报表层选择一个已发布清单，按字段检查每个标签依赖的源、完整性、版本和时间，再计算。G 不足不影响仍有覆盖的 V/M/J；旧业务评级的发布日期/有效期不能被本次报表日期刷新。

需要额外数据时生成同语义的 `backfill_request`：证券/发行人、源、粒度、所需起止/预热、目标截止、现有 dataset ID、缺失原因及预算。若任务授权了完整补齐与刷新流程，顺序执行数据 skill 后再读取新清单；单独离线刷新则明确缺失，不在渲染器里隐藏网络获取。

报表快照至少保存 `report_run_id`、`data_run_id`/清单哈希、`observation_mode`、评估截止与真实计算时间、逐源截至时间、模型/窗口/尺度/权重/种子版本、结果及每项状态、证据引用、变化和资源消耗。

幂等键由模式、评估截止、成员哈希、输入版本哈希及算法参数组成，不只用日期。相同键重试复用结果并记执行尝试；历史数据修订或新截止产生新版本。纯换排版不生成新标签点。历史补算与当时实际运行的记录分别保存/展示；数据补齐、每日执行和报表渲染不能互相冒充。

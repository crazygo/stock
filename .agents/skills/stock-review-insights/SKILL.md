# 行业环境、持仓与自选洞察

读取 `stock_review_pair_v1` 的真实运行，先解释分行业行情，再审查持仓风险，最后筛选未持仓自选机会。保留两个复杂页面作为证据入口；输出可行动的分析及依据，不把历史描述改名为未来胜率，也不执行券商交易。

## 接手已有运行

- 先读目标仓库 `AGENTS.md`、`analysis/ai_value_chain_map_v1/ONE_RUN_UPDATE_SOP.md` 的“双页面日线更新”配置及 `analysis/stock_review_pair_v1/README.md` 的重算、审查和导出规则。当前仓库为 `/Users/admin/Code/stock`；换机器时定位实际 checkout，不假定相同绝对路径。
- 用户指定的 run 优先；默认固定 `.cache/stock_review_pair_v1/current` 实际指向的已发布目录。最新修改目录可能是失败、重算或未发布尝试，不能代替 current。记录 `base_run_id`、`data_run_id`、`report_run_id`、信息截止、逐市场截止及成员取得时间。
- 用附带脚本读取并校验共用数据引用、筛出持仓/未持仓自选、提取已有指标和行业样本统计。脚本只读，不联网、不重算原模型、不生成买卖结论：

```bash
python3 .agents/skills/stock-review-insights/scripts/build_context.py \
  --run .cache/stock_review_pair_v1/current \
  --output /absolute/path/to/new-insight-run/context.json
```

指定比较基线可加 `--baseline /absolute/path/to/previous-run`。默认只读当前批次，不把“未指定基线”视为“没有变化”。输出文件必须新建，不能位于源 run 内。跨 checkout 使用 `--repo /absolute/path/to/stock`；离线导出包使用其实际 run 路径。

- 不将大 JSON 全量展开给模型；先读取计数、行业聚合和持仓/自选代码，再按候选读取指标和引用。`context.json` 中的行业 ETF 与价值链样本是两种观察。样本范围、重叠分组、证券分母与缺失行业须展示；未验证的 ETF 类型、杠杆/反向属性及不完整行业标签单列，不能把 ETF 自身涨跌当成行业所有公司涨跌。

## 两种分析时点

**已有批次回看：** 使用冻结输入和原截止；不联网、不刷新成员、不修改原指针。可以解释当时的行业环境、结构风险和候选，当前新闻及可买卖状态显示未核查。用户要求纯重算时使用 README 的 `--from-run ... --recompute --no-publish`，不能用刷新数据代替重算。

**当前洞察：** 以已有 run 为历史背景，建立独立 `insight_run_id` 和新的信息截止。核对当前持仓/自选成员、相关最新行情及重要消息；任何补充信息都有自己的来源与真实取得时间，不写回旧 manifest、不冒充旧截止已知。复用 `members_worker.py` 的只读查询和可终止执行方式，查询失败保留旧成员时间，并将“是否仍持仓/是否未持仓”标待确认。缺口按数据 SOP 补齐，不为写洞察默认再跑整个行情池。

用户没有指定时默认当前洞察；若无法取得所需当前证据，交付已有批次分析和明确缺口，不能把它称为实时卖出或买入提醒。对于当前金融事实、公告及产品属性，使用当次查询的官方来源核验。

## 分析顺序

1. **行业环境放第一位。** 按市场分开看宽基、行业 ETF、业务行业与 AI 价值链样本。读取附带 [分析与交付契约](references/insight-contract.md) 中的环境定义，比较 5/20/60 个交易日价格方向、相对强弱、组内上涨广度及分化；解释环境对已有持仓和候选的影响。以数据判断顺风、逆风、分化或未知，允许证据冲突，不先强行给全市场单一结论。行业覆盖不足须在首段说明。
2. **持仓退出预警与重要新闻。** 对每个真实持仓登记覆盖。优先核查重大负面事实、原持有逻辑失效、用户已给退出规则的触发和明显结构变化；重要利好同样报告。按契约区分“立即退出预警”“优先核查风险”“重要新消息”“暂无新增已核实事项”；未检查保持未知。“立即”需要当前持仓及事实成立、时效与操作可行性证据，单个描述指标或旧收盘不能直接触发。
3. **未持仓自选机会。** 候选来自实际自选/特别关注且排除全部已持仓证券；仅 AI 股票池成员不自动成为用户自选。先看行业背景和相对强弱，再核查业务/行业地位、近期事件、价格已反应程度及风险。给“值得考虑买入”必须写支持证据、适用的持有思路、当前价格与状态、失效条件及缺口；不足则给待核查候选，允许无新增。

新闻获取复用实际安装的 `stock-news-catalyst`：读取其 SKILL.md 及 `references/sources-and-cases.md`；代码/发行人检索、NEWS 与 NOTICE 分开，官方 IR/正文/SEC 优先。工具或 skill 缺失按渠道不可用处理，不编造新闻正文。原 run 的 `news=not_connected` 不意味着无新闻。默认沿用 SOP 的网络预算及最多 20 个发行人，优先持仓重大风险、行业事件和少量高优先级自选；登记选择理由和未检查名单，用户给定范围/预算优先。

## 选择、保存和交付

- 阅读 [分析与交付契约](references/insight-contract.md) 后保存 `context.json`、补充事实与查询覆盖、`insights.json` 和 `message.md`。每项结论区分事实、解释、反证、未知、行动条件，引用 base run 的结果路径/证券/窗口和新闻原文。相同 report ID 重算或同一新闻转载不制造“新洞察”；修订保留关联和原判断。
- 保存到 `.cache/stock_review_insights_v1/runs/YYYY-MM-DD__insight-<uuid>/` 或用户指定新目录。不改已封存运行、行情版本或双页面发布指针；当前新事实属于新 insight 的 inputs。默认不创建调度、不发送外部消息、不下单、不上传 R2。
- `message.md` 固定阅读顺序为行业环境 → 持仓预警/新闻 → 未持仓自选机会。默认突出最多 5 条实质股票事项；已核实的紧急持仓事项全部列出，不因数量上限隐藏，其余可少报或“无新增”。同时给已查/未查分母、截止、base run 与两个冻结页面的入口。v3 仅对本批次有详情的证券支持 `detail.html?code=...`；v2 当前没有代码查询参数入口，给冻结页面和搜索/选择证券的方法，不伪造单股深链。
- 分享时把引用物化到独立离线包，原双页运行使用 README 的 `export.py`；洞察补充输入、来源摘要、哈希及相对链接一并保存。普通洞察运行只引用共用对象，不逐 run 复制原始 Parquet。缺文件、依赖或来源时明确离线覆盖限制。

## 验收

确保行业部分先于个股；持仓与未持仓自选集合无交集；缺数据/未查新闻不变成无风险；信息截止后证据不回填旧运行；每条紧急或买入提醒都有时效、依据、反证和可行性；同数据重跑及同事件转载不重复发新提醒。检查引用哈希、冻结页面详情链接与输出目录，记录检查通过、部分完成和失败。格式检查通过与投资效果验证分别报告。

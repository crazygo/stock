### 已有运行上的三类洞察

任务要求基于运行产生行业、持仓和自选洞察时，使用 [stock-review-insights](../../.agents/skills/stock-review-insights/SKILL.md)。固定已发布批次及可比基线，先分析分行业环境，再给持仓退出预警/重要新闻，最后筛选确认为未持仓的自选机会。现有指标是历史描述，不直接充当买卖门槛。

该 skill 把已有批次回看与当前洞察分开：回看沿用冻结截止；当前判断另存 insight 运行、核对成员/行情并按新闻 skill 补充事实。新事实不能写回旧运行或冒充旧截止已知。交付 `context.json`、证据与覆盖、`insights.json`、`message.md` 和来源清单；新闻未接入或未检查保持未知。双页面 `run.py` 仍不自动调用新闻与洞察流程，任务明确要求洞察时再使用该 skill。

完整报告任务先执行 **P08 行业与逐股分析**，再执行 **P09 研判与消息呈现**。执行顺序为：数据准备 → 两套描述计算 → 行业及逐股分析与档案 → 重点筛选与消息 → 验收和交付。双页面配置先校验发布核心证据页，固定已发布 base run 后生成独立的 P08/P09 结果；核心页面更新不等于逐股分析或摘要已完成。单独运行 `stock_review_pair_v1/run.py` 仍只完成数据与双页部分。

## P08 行业与逐股分析

行业趋势和每股分析是 P09 的中间产物。先保存整个目标池的分析，再决定哪些事项进入消息；消息数量上限不限制分析数量。每股决策档案承接持续积累的历史证据，本次逐股分析说明这些证据在当前截止下是否仍适用、发生了什么变化。

**目标池：** 至少覆盖本次实际持仓与实际“特别关注”的并集，按完整证券身份去重，保留两个角色标记；重叠证券分析一次，最终按持仓角色呈现。查询失败保留成员时间与待确认状态，不能删掉无法确认的证券。其他自选、AI 核心池和临时领涨池保留既定数据与扫描范围；需要同等逐股分析时显式登记扩展范围。数量来自当次成员快照，不沿用 55、68 等旧批次数量。

**执行次序：** 固定基础批次及可比基线，使用 `stock-review-insights` 的只读脚本提取上下文；当前模式取得必要补充事实、固定新的信息截止后，先生成分市场行业分析，再逐一处理目标池。行业分类未知时仍分析该证券，所属环境标未知。原批次截止、各历史研究截止和本次分析截止分别保存。

| 中间产物 | 必须完成的分析 | 对 P09 的用途 |
| --- | --- | --- |
| 行业趋势 | 分市场、宽基、普通行业 ETF 和 AI 价值链样本，更新可评分 5/20/60 交易日方向、相对强弱、广度、分化及相对基线变化；保留覆盖分母与反证 | 给每只证券明确的行业背景；局部样本不能冒充全市场 |
| 每股本次分析 | 对每只目标证券检查行情与覆盖、方向/折返/形态及变化、相对行业表现、相关历史记忆、已取得新闻/业务证据、风险和下一核查条件 | 为重点筛选提供同一截止下的逐股依据，不能先按涨幅挑少数再补分析 |
| 持仓分析补充 | 核对持有依据、已有计划和退出条件；缺成本或计划时明确未知，不推算盈亏或已触发止损 | 形成风险、重要消息及需优先处理的候选 |
| 特别关注分析补充 | 检查关注逻辑、支持与反证、价格已反应程度、条件是否改善或减弱；实际已持仓者保留双角色 | 未持仓身份核实后，才可进入相应自选机会类别 |
| 每股决策档案 | 追加本次分析及来源，保留历史特征、相似情境、规则状态和待验证问题；个人计划/决策仅引用已有记录 | 用户从短消息进入完整单股 HTML；未入选股票也可以查阅 |

每条逐股记录至少保存：`security_id`、角色、来源 run/哈希、信息与行情截止、行业分析引用、各分析维度状态、事实、解释、反证/未知、相对基线变化、相关记忆引用、风险/关注条件、下一检查条件和详情路径。没有可比基线不写“无变化”；只有已检查范围内才可写“无新增”。新股票没有历史记忆也保留本次分析和补齐事项。

**全量分析与专项深研：** 每次更新都遍历目标池并留下分析结果；有效的业务或历史证据可以复用，但保留原证据日期，不每天重新深读或重训所有股票。新闻新查仍受预算约束；已有材料检查、当次新查、未请求、来源失败分别记录。最多 20 个发行人的新闻预算不能用来缩减逐股分析集合，也不能将余下证券写成“无消息/无风险”。关键输入未核实则该股为 partial，预算不足以完成目标时整体为 partial。

**保存和交接：** P08/P09 可以使用同一个日期加 UUID 的独立 insight 运行，分别保存阶段状态。在已有双页运行外保存 `results/industry_analysis.json`、`results/stock_analysis.json`、`validation/analysis_coverage.json` 及目标池每股 HTML；原始行情仍引用共用不可变对象。完整日报模式也采用这些结果文件。它们是 coder 要实现的产物契约，不是现有脚本已支持的参数。P09 的候选引用这些分析记录及哈希，所有目标股票可以从目录打开，不能只生成入选股票详情。

**P08 完成验收：** 目标池 N 只，恰有 N 份本次分析记录，角色可核对；统计 `complete / partial / blocked`，三者合计等于 N，另列未遍历/未分析清单，未遍历者记 blocked。逐维度覆盖与新闻覆盖另算，不用“生成 N 个页面”替代分析完成率；有 partial/blocked 或成员范围未核实，不能称全量完成。P09 可以交付明确限于已完成范围的部分摘要，但不能称全池已筛查。未入选股票仍保留结果和选择状态。

现有 `stock_decision_memory_v1/initialize.py` 导入已发布历史形态结果，`render.py` 合并历史底稿与固定小时研究形成单股页，尚未执行本节要求的当次行业更新和目标池全量研判。2026-10-09 核对的阅读版本有 68 只证券、55 份日线底稿、20 份小时研究，属于来源快照覆盖，不代表当前成员或每日分析覆盖。接入时复用其档案结构和单股 HTML，不将旧材料渲染当成当次分析。

## P09 研判与消息呈现

职责是从 P08 已保存的行业与全量逐股分析中筛选用户优先阅读的判断，说明什么值得查看、为什么重要、哪些条件已经改变，以及下一步应核实什么。它包含重点研判、证据审查和编辑，不把描述指标直接转成买卖门槛。分析与结构化字段沿用 [stock-review-insights 的交付契约](../../.agents/skills/stock-review-insights/references/insight-contract.md)，全量覆盖要求以本节和 P08 为准，不能沿用先选候选再读取少量指标作为完整分析。

**输入条件：** 取得 P08 的行业、逐股结果与分析覆盖，固定其来源批次；用户指定的已发布批次优先，默认解析共同 `current` 指针取得实际目录。校验 manifest、输入哈希、`base_run_id`、`data_run_id`、`report_run_id`、逐市场截止、成员来源及两页可用状态。部分批次或部分分析可以进入，但首段保留覆盖限制；失败、尚未发布或仅修改时间较新的候选不能冒充已发布批次。比较必须有明确可比基线，未指定基线不代表无变化。

| 环节内步骤 | 处理内容 | 必须交付的依据 |
| --- | --- | --- |
| P09.1 固定上下文 | 校验 P08 结果、完整目标池及阶段覆盖，复用只读脚本提取的上下文，不重算原模型 | `context.json`、行业/逐股分析及其哈希、源批次身份、成员和各源时间；上下文提取不等于已分析 |
| P09.2 区分分析时点 | 沿用 P08 的 `frozen_review` 或 `current_insights` 及固定截止；重点补证产生新截止时，重新形成受影响的 P08 结果再筛选 | 新事实存本次 insight inputs，不回写原批次或已封存分析；原截止与新分析截止分别保存 |
| P09.3 形成重点研判 | 从全量结果筛选行业重点、持仓预警/重要消息和确认为未持仓的自选机会，区分关注优先级和分析覆盖 | 事实、解释、反证、未知、支持/失效条件及逐股结果引用；不因候选少而提升证据等级 |
| P09.4 编辑消息 | 将研判组织成行业 → 持仓 → 未持仓自选的固定阅读顺序，保存所有候选及选择/排除理由 | `insights.json`、`message.md`，实际可用的冻结页面/详情入口与来源 |
| P09.5 验收和封存 | 检查集合、截止、证据、链接、去重、未查状态和紧急事项完整性；封存独立 insight run，再交付消息和报告包 | 独立 manifest、校验及验收记录；原 base run 和共同发布指针不改写 |

消息的三部分各回答以下问题：

1. **行业环境。** 分市场看宽基、普通行业 ETF 和 AI 价值链公司样本；用完整 5/20/60 交易日变化、相对强弱、样本上涨广度和分化说明背景。先列实际覆盖，局部样本不能代表全市场；环境结论必须说明对随后持仓和候选的影响。
2. **持仓预警与重要消息。** 区分立即退出预警、优先核查风险、重要新消息与已检查范围内无新增。立即退出需要当前持仓、既定退出规则触发或持有逻辑实质失效的事实，以及及时行情和交易可行性；旧收盘或单个图形不足时保留核查级别。利好、利空及混合消息都可进入。
3. **未持仓自选机会。** 来自实际自选/特别关注并排除全部持仓，结合行业背景、业务依据、价格结构、消息已反应程度及风险形成候选。当前证据不足时标待核查；只有 AI 池或临时领涨池身份不能自动进入这类买入候选。

下文七类 insight 保留为分析内容标签，由上述三部分组织消息，二者不是相互替代的分类。临时 AI 新发现和研究结果复盘可以在相应报告另设区域，不能混入确认为未持仓自选的集合。

**呈现优先级：** 行业背景始终在消息第一位，持仓部分内部先列紧急事项。普通实质股票事项最多突出 5 条；已核实的紧急持仓事项全部保留，此配置优先于下文一般数量上限。无新增时如实说明，不强行生成机会；已查、未查、来源失败与事实无新增分别展示。

**保存与分享：** 使用 `.cache/stock_review_insights_v1/runs/YYYY-MM-DD__insight-<uuid>/` 或用户指定的新目录，保存 context、补充 inputs、insights、message、manifest 和 validation。用 `base_run_id` 与哈希关联双页批次，保留本次独立身份及截止。普通运行只引用共用对象；独立分享时按双页 README 的 `export.py` 物化来源批次，再附本次补充事实、摘要、哈希与相对链接，按下文冲突保留规则合并。

**P09 完成验收：** 引用 P08 的全量结果与覆盖，摘要入选数不充当分析覆盖数；行业先于个股；持仓与未持仓自选不重叠，成员查询失败不默认未持仓；每条判断有窗口、源批次、证据/反证及下一条件；未查新闻不写成无风险；同一 report 重算或转载不制造新提醒；紧急事项不被截断；消息能进入实际冻结页。v3 对有详情的证券使用真实 `detail.html?code=...` 入口；v2 目前没有代码查询参数，给页面及搜索/选择方法，不伪造深链。分别记录数据更新、描述计算、P08 逐股分析和 P09 呈现的完成状态，格式或脚本测试不作为投资效果验证。

现有交付为 skill、分析契约和只读上下文提取脚本；`run.py` 尚未自动串起 P09，创建 skill 不等于已经查询当次新闻、完成实时预警或发出消息。完整任务若只能交付冻结回看，明确标明该范围及当前证据缺口。

### 行业环境 · 价格证据的默认展示

首页该区域默认使用 [industry_price_evidence_v1](../stock_review_insights_v1/README.md) 的图形展示。**原表是绘图数据源**：价格只取表中已显示的百分比，逐项核对 `results/industry_analysis.json` 中对应窗口；样本数、上涨分子/可评分分母、未知数和解释沿用同一批次。数值或身份不一致则停止渲染并记录失败，不另取行情、不重算分析、不提升 partial 状态。原表和解释保留在“查看原始表格与解释”中供审查。

- **同时比较三期：** 5/20/60 官方交易日并列；正负价格变化围绕零线绘制，标出准确百分比。同一区块三期使用共同线性刻度，区块之间明确使用独立刻度，不以柱长跨区块比较。
- **分开呈现：** 各市场宽基/行业基金、AI 价值链样本分别展示；每组 ≤3 只的小样本单独成区。保留原表相对顺序，组内证券数始终可见。小样本划分是展示规则，不是投资准入条件；当前成员和重叠分组不代表全市场或历史 PIT。
- **价格与广度分开：** 长条为价格变化，细条为上涨家数/可评分家数；保留分数和未知计数。缺失价格显示“未知”，广度分母为零显示“不可评分”，不得画作零收益或零胜率。
- **可检查与离线：** 点击/键盘选中行后，展示该组三期数值与原表解释；展示逐市场真实行情截止、窗口、单位及行业 ETF 实际覆盖。全部绘图数据、CSS 和 JS 内嵌，不依赖 CDN；桌面与窄屏不裁切数值、不出现页面横向溢出。

P08/P09 的首页与原表生成后，**写 manifest/checksums 和封存之前**执行：

```bash
python3 analysis/stock_review_insights_v1/render.py --staging <本次未封存目录>
```

该步骤只替换首页行业价格区域，保存 `results/industry_table_data.json` 与 `validation/industry_price_evidence.json`。将 `render.py`、`industry_price_evidence.html` 和 `verify_browser.cjs` 复制到本批次 `repro/source/` 后，完成宽屏/窄屏、鼠标/键盘、原表核对、详情返回及断网验收，记录浏览器结果，再按原流程封存和打包。可按模块 README 运行浏览器检查器。现有双页面 `run.py` 不会自动执行 P08/P09；接手 coder 按本 SOP 完整报告顺序执行这一渲染步骤。

仅替换已封存报告的展示时，使用 `--from-run <原目录>` 生成新的 `run_kind=render` 视图，登记原批次及输入哈希，沿用原截止与分析状态；不得回写旧报告/旧 ZIP 或将其称为新分析。本地视图可复用原运行的相对链接；独立分享必须物化全部依赖，重新校验和打包。

## 独立目录与产物

默认根目录为 `analysis/ai_tracking_daily_v1/runs/`。写入前确认全部生成目录被 Git 忽略；必要时只增加这条目录的忽略规则。原始行情 Parquet 不进入 Git，R2 仍采用人工校验后归档的约定。

目录名采用 `YYYY-MM-DD__run-<uuid>`，日期为上述 `run_date`。例如 `2026-10-08__run-<uuid>`。先写入同根目录的 `.staging-<run_id>`，完成校验后原子改名为正式目录。失败也保存独立目录和失败清单，不覆盖已有运行。

```text

  manifest.json                # 输入与全部产物的版本、路径、哈希和依赖

  index.html                   # 可离线打开的本次报告首页
  comparison.html              # 本次多股票形态/日周图比较页
  inputs/
    members.json               # 成员、分组、来源、取得时间与增删
    data_manifest.json         # 本次事实清单原样保存；包内路径映射写在 manifest
    quality.json               # 实际使用的产业链、初评、核查和有效期快照

    stock_analysis.json        # P08 目标池每只证券本次分析，含未知/阻塞

    US_NVDA.html               # 示例文件名；实际按证券身份生成详情
```

这是目标产物契约，文件名不是已存在的程序接口。不适用的结果文件仍保存 `status`、原因和记录列表，不能仅省略文件让接收者猜状态。不得把外部可变 `current.json`、软链接或机器绝对路径作为唯一依赖；实际使用的成员、证据摘要、日历、价格和参数复制成包内快照，保留原来源与哈希。原数据清单原样保存及核验；包 manifest 另存 `portable_path_map`，把原引用映射到包内相对路径，不修改旧清单后继续沿用其旧哈希。

`manifest.json` 至少包含 `schema_version=ai_tracking_bundle_v1`、`run_id`、`run_date`、`run_kind`、`status`、起止时间、信息及市场截止、成员范围、各模块状态、`data_run_ids`、`report_run_id`、基线/父运行、算法版本，以及逐输入/产物的相对路径、SHA-256、字节数、记录数、来源和覆盖。它列出其他产物，不给自己计算自引用哈希；`checksums.sha256` 包括 manifest 和其他文件。

包内身份使用完整 `security_id` 和独立 `issuer_id`。运行 ID、事件 ID、insight ID 与证券代码分别保存；跨运行复用的同一事件保留稳定关联，修订追加版本。消息选择属于本次运行，保留真实选择时间。

代码提交 SHA 不足以复现未提交代码，必须保存实际用到的最小分析与渲染源码及哈希。复现所需配置使用无凭证的参数快照，R2、OpenD 地址等取数配置不成为离线重算依赖，不复制账户配置。分享材料只需持仓成员标记，不含账户号、金额、持股数或凭证；新闻保存来源及许可范围内摘要，不打包整篇未经许可转载。

## Insight 与消息筛选

前六类服务于当次股票细查，第七类服务于后续复盘。每类只有取得对应输入时才输出结论。P09 将这些内容按行业环境 → 持仓 → 未持仓自选组织，不按下表逐类平铺消息。

| Insight | 最少回答的问题 |
| --- | --- |
| 新形态与上涨动因 | 新拉升或 V 深弹发生在哪个窗口；此前下跌和之后反弹各有什么候选解释；消息是否早于启动，价格已反应多少 |
| 阶梯中继进展 | 哪个真实平台延续、突破或减弱；较上次哪些依据改变；下一确认和失效条件是什么 |
| 风险与原判断失效 | 冲高回落、结构破坏或催化反证改变了什么；三日观察还剩哪些检查条件 |
| 产业群共振与偏离 | 同群普遍变化还是个股独立变化；相对强弱、同日分母、重叠分组与解释缺口是什么 |
| 新发现的 AI 业务价值 | 新领涨证券的具体产品/服务、产业链位置及商业兑现依据；本次是新业务事实还是价格发现 |
| 业务质量与估值变化 | 新披露改变了什么经营假设，原评级是否仍有效；有版本化财务与公式才给估值变化 |
| 成熟结果与复盘 | 原观察后来支持还是失效；成熟数、未知数、失败、基准及解释改变是什么 |

筛选在 P08 全量结果保存之后进行，未入选摘要的股票仍保留分析和详情；已分析无实质新增、低优先级、证据不足、未分析分别记录，不能统称无新增。筛选规则固定为：重要反证或风险变化优先，其次新事实与新形态，再次持续结构的实质变化。每条保存 `priority_reason`、新鲜度、证据状态和相关股票，不生成未经验证的上涨概率。重复转载及同一事件的多个形态合并呈现；同一发行人多个证券共用事实，价格分开。无变化的阶梯项目保留在报告跟踪区。

每条被选消息保存 `insight_id`、类型、证券/事件引用、结论、相对基线的变化、证据、来源及价格截止、真实发现/选择时间、已反应幅度、反证/未知、下次条件和 `detail_path`。业务兑现期限与已观察价格反应时长分列；未来剩余上涨天数未验证时保持未知。

`message.md` 开头显示运行日期、信息及行情截止、状态和重要覆盖限制。其后每条采用以下格式，链接到本包单股详情的对应事件锚点：

```text
股票｜优先查看的原因
新变化：……
时效与价格反应：……
判断依据和关键缺口：……
下一检查条件：……
查看详情：stocks/<security>.html#<event-or-insight-id>
```

详情至少提供真实价格路径、完整形态窗口、新闻原文链接与时间、AI 业务位置、质量证据、变化及跟踪历史。首页按摘要 → 单股 → 事件/价格 → 来源 → 返回展开，直接链接必须能定位相应条目。没有精华时明确无新增并给覆盖状态，不用过期案例凑满五条。

三日结果仅按原观察事前登记的目标、入场参考、时段和交易日计数成熟；首次运行未登记协议时不评分。历史最高价触及与持有净收益分开，未成熟或缺少完整路径保持未知，不把五分钟行数或同一事件多次命中当独立样本。

## 独立分享与离线复现

封存后只读保存整个运行目录。至少交付完整目录，以及同名 `YYYY-MM-DD__run-<uuid>.zip` 和 ZIP 的 SHA-256；压缩包放在 run 目录之外，避免自包含。打包是本次产物生成动作，不自动发给第三方或上传。

`index.html` 和 `comparison.html` 使用内嵌数据、CSS 与脚本；单股页及来源索引使用包内相对链接。复制目录或解压到另一机器、断网打开，仍能完成摘要到单股的查看；外部原文链接明确需要联网。不得依赖原机器的 localhost、CDN、绝对路径或目录外软链接。

`replay.sh` 使用包内输入、源码、版本参数及记录的依赖，将结果写到指定临时验证目录。重算不得重新下载行情或新闻，不覆写本次目录，不增加实时发现/评估点。比较稳定分析结果的内容哈希；运行耗时和验证时间等非分析字段单独列出，不要求它们逐字相同。

## 跨机器合并

合并的是运行包及其索引，不能将两台机器不同复权序列、不同成员日或不同规则的结果拼成一份历史事实。

1. 在临时目录解包，校验相对路径、manifest、全部文件哈希与必需依赖；禁止目录外引用和路径穿越。损坏或缺依赖的包保留为导入失败，不进入有效运行索引。
2. **不同 run ID：** 各自保留完整目录，即使日期或行情截止相同；在本地派生索引中并列登记。
3. **相同 run ID、相同 manifest 哈希且全部文件校验通过：** 视为同一运行，幂等跳过，不产生新观察。
4. **相同 run ID、不同内容：** 作为冲突保留原包和来包，来包放入 `conflicts/<run_id>__<manifest-hash>`；记录冲突，不覆盖、不改原 run ID。校验文件与内容不符属于损坏，不能仅凭 manifest 一致去重。
5. 导入保留原公开、接收、计算、选择及封存时间；另记本机 `imported_at` 和导入来源代号，不能把导入日期写成原发现日期。
6. 运行根目录外维护可重建的 `registry/runs.jsonl`，以 run ID 和 manifest 哈希登记路径、截止、状态、父运行、冲突及导入时间。索引写入加锁，合并顺序不改变运行内容。
7. 数据、事件和评级有修订时以版本关联并存。选择比较基线须显式保存；不能按文件修改时间或导入先后自动决定“正确版本”，不自动切换其他任务 current 指针。

跨机器需要原始事实时，将包内行情输入视为经校验的本次 capture 副本，保留证券、币种、复权、时段和原始来源；进入共用行情库或 R2 的归档仍另行人工校验和执行。

## 日后复盘与运行修订

已封存运行不可改写。新事实、更正、重新分析或复盘都生成新的日期加 run ID 目录，登记 `parent_run_ids`；替代同截止分析时另记 `supersedes_run_ids`，保留原结论和消息选择。

复盘运行使用 `run_kind=review`，引用原 `insight_id`、当时理由与截止，另存后续实际路径、成熟标签、失败/未知及解释修订时间。共享复盘包时附实际用到的原观察快照和后续输入，不依赖接收机器恰有父包；父包 ID 与哈希仍保留。

只重渲染采用 `run_kind=render`，引用原 `report_run_id` 和输入哈希，保存新视图而不制造新评估点。中途恢复只复用尚未封存的 staging 与真实 attempt 日志；正式目录存在后需新 run ID，不能打开它继续写。

## 验收与完成条件

`validation/acceptance.json` 为每项记录 `pass`、`fail` 或 `not_verified`、证据相对路径及原因。部分分析可以分享，但必须显示 `partial`；不得把关键交付或可移植验收失败标为完整成功。

- **实际更新：** 本次截止、成员和输入驱动计算；截止后事实隔离。没有新行情时如实说明，不以修改时间证明更新。
- **覆盖与证据：** 请求、实际、可评分范围分别展示；缺失、过期、未检查、源不可用与检查后无新增分别记录。初评与核查等级分开。
- **全量分析：** 行业趋势先于逐股研判；实际持仓与特别关注并集有逐股记录及完整状态分母，未入选证券仍可打开档案。分析覆盖数、新闻覆盖数和摘要入选数分别展示，未遍历或关键维度缺失不标完整成功。
- **消息到详情：** 对每条精华验证消息链接 → 对应证券/事件 → 真实价格及证据 → 来源 → 返回；桌面与窄屏可用。没有精华时验证无新增状态。
- **行业价格图：** 图中所有价格标签、样本数、广度分子/分母、未知数与原表及 P08 对应记录一致；三期共用区内刻度，各市场及小样本分开，缺失不补零；原表可展开，选择/键盘/详情返回有效，断网仍能绘图。保存实际浏览器宽窄屏与一致性验收记录。
- **形态与时点：** 日线/5m 规则和参数独立，真实发现与历史回算分开；零量 bar、迟到新闻、重复事件及无历史基线不会制造启动或跟踪历史。
- **离线可读：** 将产物复制到不同路径，断网完成首页、比较、单股和事件查看。记录实际路径与截图。
- **离线可复算：** 使用包内输入和源码重算一遍，稳定分析结果一致；依赖缺失明确失败，不偷偷取新数据。
- **合并幂等：** 在隔离目录演练不同运行保留、同包重导去重、同 ID 内容冲突保留双方，以及损坏文件拒绝导入；真实第二台机器未检查时标明验证范围。
- **封存完整：** 全部哈希与相对依赖有效，原实验输入及全局页面未被改写；无原始行情或凭证误入 Git。

执行失败仍交付运行目录、错误、已完成部分和可执行的下一步。最终给用户一条精华消息，并附运行目录、首页、比较页、ZIP、manifest/哈希、数据与分析覆盖、验收状态、耗时费用和未完成项；只能报告实际执行过的命令和真实验证。

# AI 产业链股票研究与报告 SOP

登记日期：2026-10-07。状态：任务拆分与报告设计。

目的：持续积累 AI 股票的行情、业务和事件证据，形成能帮助选股、观察三日持有机会及检查研究效果的报告。每份报告先给出有依据的变化与判断，再提供股票地图、时间线和可追溯明细。

本轮用户明确了两条主线：日粒度跟踪报告服务于多股票形态比较和选股，由 `stock-data-backfill` 与 `stock-report-refresh` 负责；已有 5 分钟 K 线积累服务于三天持有研究，目前尚未形成报警机制。以下把此前讨论的动因、影响时间、阶梯中继和动态股票池纳入任务清单，并补充结果复盘及报告精华的要求。

本文是待建设任务的 SOP，不代表已经启动自动任务或通知。详细数据与形态边界沿用 [跟踪流程规格](TRACKING_REQUIREMENTS.md)，基础交接沿用 [数据契约](../../.agents/skills/stock-data-backfill/references/data-contract.md)。

交给 coder 做一次实际更新时，使用 [一次更新执行 SOP](ONE_RUN_UPDATE_SOP.md)：包括七类 insight、精华消息到单股详情，以及日期加唯一 run ID 的独立目录、输入快照、离线分享、复现、跨机器合并与后续复盘规则。

## 日报基础的十项每日动作

以下是 T01 的目标流程，尚未启动定时执行。每次运行都登记检查结果；行情推进以各市场官方交易日及完整日线就绪为准，非交易日记录无新行情，不能补造 K 线。

| 顺序 | 每日动作 | 当日可检查的产物 | 责任 |
| --- | --- | --- | --- |
| D01 | **确定本次范围与截止。** 选定最近已完成交易日、信息截止、成员选择规则、算法版本和预算；检查已有任务占用，避免并发覆盖同一发布指针 | 运行登记及目标截止 | 两个 skill 交接 |
| D02 | **保存成员与分组。** 读取真实持仓、自选与特别关注，引用选定 AI 池及等级；比对增删，保留核心池和历史成员来源 | 成员快照、分组快照及增删清单 | backfill |
| D03 | **检查数据缺口。** 逐证券检查行情新鲜度、请求范围与实际覆盖、内部缺口、复权一致性，以及业务证据和评级有效期 | 补齐清单、覆盖与到期清单 | backfill |
| D04 | **补齐或修订行情。** 按 Local → R2 → OpenD 获取所需日线；新成员补所需历史，公司行动造成复权变化时另存完整一致版本；保留失败和非美股支持范围 | 新行情版本、来源与修订记录 | backfill |
| D05 | **发布本次事实清单。** 固定成员、行情、产业链、初评和核查评级的版本及哈希；有新披露时关联已取得的事实，过期和未接入来源显式保留 | 可复算的 `data_run_id` 与不可变 manifest | backfill |
| D06 | **计算当天描述。** 对本版成员计算五标签、象限、四种日线上涨形态及周线；覆盖不足逐项标未知。日线与 5m 形态分别保留算法和结果 | 标签、形态、价格投影与覆盖快照 | refresh |
| D07 | **比较并更新持续观察。** 与上次评估比较实质变化；检查已登记阶梯项目的延续、减弱、失效或待确认，保存真实状态更新时间 | 变化表、持续跟踪记录 | refresh；跟踪账本待接入 |
| D08 | **形成日报精华。** 选出最多 3–5 条有依据的变化，说明时效、原因假设、反证和下一检查条件；可少报或无新增，未取得新闻不编造动因 | 保存当时选择理由的 insight 条目 | refresh |
| D09 | **生成并校验候选页面。** 从同一批保存结果生成本页，检查输入版本、截止、覆盖数、缺失显示、图表与详情能打开；交互变更另做完整页面验收 | 候选 HTML、校验结果及错误 | refresh |
| D10 | **发布并记账。** 校验通过后替换当前页面，保留历史结果；失败保留上次可用页。记录最近成功、最近尝试、缺口、耗时和预算消耗 | 可打开的日报、`report_run_id` 与运行账本 | refresh |

同一数据和规则重跑复用结果；纯页面重渲染不增加评估时间点。部分数据可以发布有明确缺口的报告，不能将全页标为最新；不满足指标覆盖的证券仍保留在池中。每日验收必须看到行情截止真实推进和页面引用本次结果，不能只看到文件修改时间变化。

新闻与公告每日增量检查（T03）、领涨榜与 AI 临时池（T04）、三日观察结果成熟（T07）是另外三项日常任务，建设后与日报基础共用数据清单并向报告提供内容。5m 扫描与报警属于 T02 的盘中任务，不能用收盘日报替代其时效要求。

全池业务深读、完整重评及重新训练不列为每天重复工作；新财报、重要商业事实、证据到期、新成员或规则修订才触发相应专项任务。已有证据的检查时间可以更新，证据截至日和有效期不能因生成日报而自动延长。

## 每个任务的固定 SOP

每个任务都应完成以下顺序，并保存自己的运行账本。

1. **固定范围和截止。** 登记证券池版本、数据粒度、市场时段、信息截止、算法版本、预算和本次目标。
2. **检查输入覆盖。** 消费已发布清单，核对完整范围、内部缺口、来源时间和证据有效期；缺数据生成明确补齐请求。
3. **形成可追溯观察。** 计算当前状态与相对上次的变化。事实、解释假设、反证和未知分别记录；重复事件复用关联，修订保留旧版。
4. **决定报告位置。** 首次重要发现、结构失效及新事实优先；持续未变的项目保留在跟踪区。选择理由在当时保存，不能在未来结果出现后补选精华。
5. **保存后发布。** 先保存结果及来源引用，再渲染报告。失败不替换上次可用页面，显示最近尝试和原数据截止。
6. **追加后续结果。** 结果窗口完整后写成熟标签；原观察、当时解释和报告选择不回写。未知与失败保留，进入复盘。

底层数据积累、观察计算、报告渲染及通知是分别登记的动作。纯渲染不增加观察点；电脑睡眠后可以补事实与结果，但不能补造过去已经报警或已经运行的记录。

## 选股日报的精华内容

地图帮助横向比较，精华区说明哪些变化值得进一步查看。建议每次最多突出 3 至 5 条有实质变化的判断，没有足够结论时可以少报或明确无新增。

日报重点包括：

- **形态变化**：方向或波动画像改变，变化发生在什么范围、相对上次有多大；五标签是描述，不改称上涨概率。
- **持续结构**：阶梯候选得到确认、延续、减弱或失效；没有变化的跟踪项目仍保留。
- **业务变化**：新事实支持或削弱原 AI 业务判断，相关评级的证据是否仍有效。
- **产业群环境**：个股变化是否与其产业群共同出现，或只是少数成员变化。产业群分组和价值传导已讨论过；将群内收益分布、上涨覆盖和个股相对表现接入日报，是本轮新增的组合分析建议。价格共同变化不证明业务传导因果。

价格图形、业务质量和估值同时可查，但不合成一个未经验证的选股概率。已有股票池和历史批次继续保留；低覆盖证券能打开详情，不能用填零或删除营造完整地图。

## 分钟观察与三天持有的衔接

分钟任务记录首次可确认形态及系统真实发现时点，使用此后可取得的参考价格观察三日路径。既有扫描研究统计的是形态之后「三天内最高价触及 +5%」等历史指标，这与「实际持有三天后的净收益」不同。

服务于三天持有时，需要同时登记三类结果：

| 结果 | 说明 |
| --- | --- |
| 机会触及 | 是否在规定窗口内达到预先登记的目标、首次触及时点、路径覆盖 |
| 持有表现 | 按预先登记的入场延迟、价格参考、成本及退出规则计算收益；尚未定义时保持未评估 |
| 持有期间风险 | 入场参考后的最大回撤、结构失效、催化被否定、缺失和数据过期 |

三天计数、是否包含启动当日、允许的入场时段、目标、止盈止损及最长持有期退出规则，都应在效果评价前登记。本文不把旧扫描的隐含假设当作已确认的持有协议。没有真实成交记录时，只能报告按协议计算的观察或模拟结果。

建议报警只对应可解释的状态变化：首次确认的新事件、跟踪结构失效、重大新事实或原解释被证伪。连续 bar 对同一事件的重复命中更新跟踪，不重复报警。数据过期时停止产生新的「当前机会」，显示覆盖问题。

报警的渠道、交易时段、去重、静默条件、可接受延迟及睡眠恢复行为尚待登记。形成观察页和可靠状态账本后，再接入通知；本文未开启外部消息或定时任务。

## 精华条目的固定格式

每条 insight 应回答以下问题：

| 内容 | 必须说明 |
| --- | --- |
| 结论 | 哪个证券或产业群发生了什么，为什么值得优先研究 |
| 变化 | 相对上次报告，价格结构、业务事实或证据有哪些新增变化 |
| 依据 | 行情窗口、新闻或公告来源、数据和证据截至时间 |
| 解释与不确定性 | 已核实事实、解释假设、反证及影响判断的缺口 |
| 时效 | 实际发现时间、已观察持续时间、下次里程碑或失效条件 |
| 下一步 | 需要查看或核实什么；条件改变时怎样更新判断 |

每条结论可以打开对应证券的价格与事件时间线，核对原始依据。用同一批数据生成的不同算法结论不当作多份独立证据。报告精华可以包含「原判断失效」或「目前无法解释」，不只呈现看涨案例。

## 新发现与业务复查如何控制工作量

每日领涨临时池先保存原始榜单，再匹配已有发行人和有效资料。新发行人完成低成本 AI 路径核查；有价值的商业事实、重要持仓或少量补证即可完成核查的候选，再进入重点复查。

新发现卡片至少包含 AI 产业链位置、具体产品或服务、商业兑现证据、本次上涨的候选解释、质量核查状态和下一检查条件。涨幅大不自动代表业务好；资料未取得不降为 B。临时观察到期转归档，历史成员和事件保留。

T06 复用既有 `ai-stock-rating` 的初评与逐股核查分工。新财报和重大商业变化触发更新，同一未变财报不重复深读；有效期不因报告刷新自动延长。估值新公式另行登记，财务期间和股价截止分别显示。

## 复盘周报的判断标准

周报同时评估效果和研究流程。不能只展示后来上涨的案例，也不能用每五分钟行数增加独立样本。

- **判断效果**：按冻结协议报告目标触及率、持有收益及回撤，分别给分母、成熟数、未知数、同股或同群基准和区间不确定性。三日重叠及同股相关样本须处理，不能宣称独立。
- **解释效果**：哪些催化假设获得后续业务事实支持，哪些被否定，哪些仍无法判断；保存解释改变的时间。
- **发现效果**：新增 AI 发行人、复用已有资料、待核查及覆盖缺口；当前领涨成员不反推历史股票池。
- **时效与供给**：从事实可知到发现、从发现到报告的延迟，有多少天有实质发现、重复信息多少、是否经常过期。
- **下一轮问题**：列出可检验的问题，例如是否需要新的阶梯结构规则或更完整新闻源；参数改动另升版本，不回改旧结论。

三日结果成熟入库属于持续数据任务，周报只是汇总已经保存的结果。时间尚未成熟或分钟前缀不完整时保持待确认。

## 建设顺序与完成条件

建议先完成 T01 的真实日度交付并形成稳定阅读入口，同时准备 T03 和 T04 的事实来源。随后形成 T02 的状态账本和观察页，将 T05 接入持续跟踪，再接入通知。T06 按新事实逐步补充，T07 从第一条真实发出并保存的观察开始积累，不等待全部模块完成。

| 阶段 | 可查看的成果 | 完成条件 |
| --- | --- | --- |
| 日报基础 | 多股票形态地图、逐股时间谱、变化摘要及 `ai_trend_quadrant_v2/index.html` | D01–D10 完成：成员与数据清单可追溯、全池逐项覆盖可查、真实截止推进、候选页校验后发布、历史可复算 |
| 事实与新发现 | 事件证据、新发现日报及临时成员历史 | 真正取得来源记录，失败和过期可见，价值点有可打开的依据 |
| 持续观察 | 三日观察页、阶梯跟踪、风险变化 | 首次发现时间真实、重复去重、失效和未知保留、三日口径先登记 |
| 通知 | 按登记条件发出的重要变化 | 渠道和时段确定、延迟可测、睡眠恢复不补造报警、幂等 |
| 复盘 | 成熟结果与复盘周报 | 原观察不可覆盖、效果与基准可复算、未知分母及失败完整保留 |

已有日度接入工作继续由原任务推进。本次落盘新增任务及报告契约，不启动这些任务，不修改其代码或运行中的数据指针。

# 每股决策档案策略规范

阅读入口：[每股 HTML 目录](index.html) · [SOXS 档案](pages/US.SOXS.html) · [NRG 曲线与案例](pages/US.NRG.html)。本地地址为 http://127.0.0.1:8768/analysis/stock_decision_memory_v1/index.html 。

每只证券保留一份持续积累的决策档案。买入、继续持有、减仓或卖出之前，先查它在相似情境中的历史表现，再对照本次交易事先写下的计划。档案的作用是让决策有依据、有边界，并能复盘哪些选择由情绪推动。

股票的特征会变化。每条记忆都要带上观察范围、适用情境、证据和失效条件；近期反证与支持证据一起保留。首版把已有的特别关注证券历史描述导入为底稿，并用 [SOXS 样例](SOXS_EXAMPLE.md)说明怎样从一个发现形成可检验的交易问题。当前没有经过验证的每股买卖规则。

## 每只证券积累的五类记忆

| 记忆 | 需要积累什么 | 在决策中回答什么 |
| --- | --- | --- |
| 产品与业务 | 证券身份、公司业务或基金机制、行业、杠杆与反向条款、拆合股、重要公告及其时效 | 我买的是什么，本次是获利交易、长期配置，还是组合对冲？ |
| 历史路径 | 长期与近期方向、折返频率和幅度、波动与缺口；保留原单位、日期、公式和样本数 | 现在看到的涨跌，在这只证券过去的路径中处于怎样的位置？ |
| 情境与后续 | 首次盈利达到某水平、追涨、回撤、放量、事件发生后，继续持有的收益、回吐、耗时和失败案例 | 在当时已知的相似条件下，多等一段时间的收益和风险是什么？ |
| 交易计划 | 入场理由、价格参考、持有期限、损失预算、获利处理、退出与失效条件、规则版本 | 这次交易原来准备怎么做，现在是否到了兑现计划的时点？ |
| 个人决策 | 当时想做什么、情绪、实际选择、是否改变计划、改变依据及成熟后的结果 | 我是否反复追涨、舍不得兑现或把短线亏损改成长期持有？ |

JSON 底稿导入五类记忆中的“历史路径”。每股 HTML 另引用用户指定的小时相似研究，保留曲线、同股基准、逐个历史案例和探索参数；其他项目没有证据时留空。证券类型来自成员快照；除 SOXS 样例引用的发行人资料外，类型标签不代表产品条款已逐一核验。业务质量评级、价格形态和交易规则分别保存，不合成总分。

## 每次决策读取一张参考卡

参考卡只回答与当前决定有关的问题，按以下顺序阅读。

1. **本次目的。** 本次是短线获利、较长持有还是对冲？计划持有多久？短线交易和长期配置分别建记录；SOXS 对冲仓的退出还需要检查组合的对冲目的。
2. **当前状态。** 当前价格与报价时间、实际入场成本、持有时长、当前盈利、持仓以来最高盈利及已回吐多少；行业环境和公告是否发生变化。持仓成本、仓位或当前报价缺失时，相关字段显示未知，不能用历史价格代填。
3. **相关记忆。** 最多展示三条适用证据，同时列出最重要的反证。每条显示观察日期、时间粒度、价格口径、样本和覆盖；近期与长期结果冲突时并列展示。
4. **可比较的选择。** 在相同起点上比较全部退出、部分兑现、按事先确定的跟踪退出规则持有，以及持有至约定时间。显示净收益分布、利润回吐、亏损尾部和资金占用；策略参数未登记或结果未计算时显示待研究。
5. **计划与偏离。** 原计划是什么？现在想改变哪一项？新增事实支持改变，还是只觉得“还能涨”“不甘心”？允许修订计划，但要保存原版、修订时间和当时依据。

只有足够新、情境匹配的证据，才能参与当前参考。JSON 历史底稿没有实时持仓或报价；HTML 的持仓与报价是原小时研究的固定批次快照，不能自行填出本次实时状态，也不能推导当下买卖概率。

## 盈利达到百分之五时研究什么

“历史上符合某种条件的百分之五上涨波段较少”可以提醒复核，但不能直接确定百分之五就是最佳卖点。需要从**首次可观察到该笔仓位盈利达到百分之五的时点**出发，观察随后继续持有的代价与收益。

百分之五的分母必须是实际成交与成本口径。相对昨日收盘、日内低点或事后波段低点的涨幅，是另外的事件，分别建表。持仓期间加减仓、拆合股和分红也要登记，不能把复权价格直接当作当年真实成交价。

| 待研究的问题 | 结果应如何表达 |
| --- | --- |
| 盈利首次达到百分之五后，能否再提高收益？ | 在预先登记的剩余持有期限内，进一步达到目标的次数、分母、待确认数量及不确定性 |
| 继续等会吐回多少？ | 从触发时点到固定终点的收益分布；期间回吐、止损触发顺序和最差情形 |
| 多等多久才换来额外收益？ | 达成时间分布、未达成数量、持有期限和资金占用 |
| 先兑现一部分是否符合目标？ | 同一批入场与触发事件、相同成本口径下，各退出规则的净结果和风险 |
| 哪些环境下结果不同？ | 按触发时已知的趋势、波动、时段、行业和事件状态分层；分层过细导致的样本不足保留 |

候选提醒可以是：“已到达本次获利检查点，核对原计划与继续持有证据。”具体卖出比例、目标和跟踪幅度，需要事先确定的风险偏好及独立验证；首版不替用户默认百分之五清仓，也不默认继续等百分之十。

## 证据怎样成为交易规则

每条记忆有独立状态：**历史描述、待检验假设、历史前向检验、冻结后的新数据验证、失效或待复核**。历史描述始终可以阅读；只有经过对应交易目标验证的规则，才显示其验证范围。样本不足或过期不能包装成高置信度。

研究开始前登记入场或触发定义、持有期限、价格参考、费用与滑点假设、退出规则、允许尝试的参数及评价目标。训练、阈值选择和评价按时间分开，多日标签在下一块开始前成熟；已经看过的数据属于开发历史。每股参数可以不同，但尝试过的失败参数与未通过股票一起保留。

研究样本来自当时可定义的入场规则或真实交易，不能从事后最低点开始。记录所有合格事件，再记录未来结果；成功、失败、缺失、未成熟都保留。每个预定义持仓情节只取首次触发，相邻分钟不反复增加样本。同股同日、重叠持有期及同一市场冲击下的多股结果需说明依赖关系；不重叠不等于统计独立。

命中率明确分母；同时显示信号数量、日期覆盖、同股同情境基准、净收益与尾部风险。这里不沿用旧预测工程的通过状态，也不把描述指标的高低变成未来概率。若比较多个退出策略，应固定相同入场样本；只在盈利交易中检查百分之五后的行为，不能替代整个入场策略的评价。

分钟 OHLC 无法恢复同根 K 线里高低价的先后。当目标和止损可能在同根触发时，保留歧义或使用更细证据；价格触及与可成交退出分别记录。仅有常规盘数据时，不声称已经测量盘前盘后或隔夜可执行路径。

## 日常如何积累

**交易前写计划。** 记录目的、入场依据、持有期限、最大可接受损失、获利检查点和退出条件。仓位还需结合资金占用及同一行业的相关风险；这些额度由用户确定，不从历史波动自动推导可承受损失。缺少计划时可以查历史，但“参考卡”不能声称本次已经有退出规则。

**准备操作时留记录。** 保存当时信息截止、证据版本、想采取的选择和实际决定。计划被修改时追加修订，不覆盖原记录。卖出后继续上涨本身不等于决策错误；应分别检查是否遵守当时合理计划，以及该规则长期是否有效。

**收盘后更新事实与已成熟结果。** 新行情进入既有 Local → R2 → OpenD 数据流程；行情完整性、公司行动和复权口径检查后再生成新快照。旧快照保留，新近案例追加。尚未结束的持有窗口保留待确认，缺行情不判断失败。

**每周复盘个人行为。** 检查盈利回吐、因恐惧提前退出、追涨、计划偏离和修订原因；用真实记录计数，不能根据用户一句自述填出过往错误率。过程质量与实际盈亏分别报告。

**按月复核规则与变化。** 比较近期和较长历史，检查行情状态或产品机制是否改变；历史验证到期或出现重要反证时降为待复核。重新选择参数必须另升版本，并从后续新数据继续验证。更新时优先报告重要变化和反证，无新增则说明无新增。

## 首版底稿与使用入口

运行 `initialize.py` 会读取已经发布的双页面批次，为该批次历史形态报告中的每只证券建立独立 JSON 底稿。它导入偏上行窗口占比、折返频率、完整波段幅度、峰谷确认依据及覆盖，并保存来源哈希。

底稿位于仓库的 `.cache/stock_decision_memory_v1/snapshots/<来源内容标识>/profiles/`。[证券索引](../../.cache/stock_decision_memory_v1/index.json)按证券列出历次导入；同一内容重复导入不会新增记忆，观察内容有变化时另存快照。历史快照不可改写，跨机器同一标识不同内容应保留冲突并停止合并。个人计划使用 [决策记录模板](decision_template.json)另存；新发现、假设及反证使用 [研究记忆模板](memory_template.json)，避免混入不可变的历史快照。

2026 年 10 月 8 日的首批底稿包含 55 个特别关注证券，38 个公司股票和 17 个 ETF；来源信息截止为当日 16:51:17 中国时间，美股行情截至美东 10 月 7 日、港股截至 10 月 8 日，逐股实际范围保留。来源批次整体为 partial，具体缺失与短历史按每份底稿读取。个人计划和新记忆需要另外记录；初始化命令只导入已发布的历史描述。

```bash
python3 analysis/stock_decision_memory_v1/initialize.py \
  --from-run .cache/stock_review_pair_v1/current
python3 analysis/stock_decision_memory_v1/render.py
```

HTML 覆盖 55 只特别关注底稿与小时研究中 20 只持仓的并集，共 68 只证券。每只都有独立文件；其中 55 只保留日线特征，20 只引用小时研究，19 只适用美股盘前模板，港股保留不适用。额外 13 只证券没有日线底稿，不从其他股票补数。目录支持代码／名称搜索与来源分组筛选；单股页面支持选择股票、上一只／下一只和章节跳转。

小时模块沿用 `premarket_self_analogs_v1/report.template.html` 的公式和交互，按单股嵌入冻结数据。日线特征固定在各自快照，下方小时日期与门槛控制仅作用于小时模块。新页面的目录、特征、操作检查和峰谷表使用相同的灰阶、系统字体、普通边框；没有新行情请求，也不改原研究页面。

每次渲染按 HTML 内容哈希保存在 `.cache/stock_decision_memory_v1/views/`，`index.html` 和 `pages` 是当前阅读版本的链接，旧版本保留。单个 HTML 内嵌本股阅读所需数据与脚本，离线打开仍能检查图表和样本；股票之间的导航需要同时保留其他 HTML 文件。渲染前核对数据投影与实际报告、模板重建与实际 HTML 均完全一致，并在本版 manifest 中记录实际来源哈希及来源发布清单的一致性。

向研究助手查询时，可使用：“读取 US.SOXS 的每股决策档案；本次是短线获利，当前净盈利约百分之五，计划持有至明日收盘。列出相关历史证据、反证、继续持有与兑现的已验证比较，以及哪些数据仍不足。”助手还需核对当次真实持仓、报价和信息时效。

已交付每股 HTML、策略规范、可追加的历史底稿和决策记录模板。小时相似情境沿用已有探索研究；净盈利达到检查点后的退出比较、实时参考卡、个人交易日志界面、提醒与调度尚未接通。已有双页面与旧实验保持各自入口；本次不改变任何冻结模型、门槛或观察配置。

# Offline local adapter · code review and run contract

2026-09-27. `local_adapter.py` is a P2/P3 research bridge. It reads files only, accepts a fixture ledger only, and never creates a real cohort, downloads prices, starts a service, uploads data, or connects to an account. The prior store, feature encoder, inference code, BUY ledger, and label/evaluation math retain their separate contracts.

## Input and execution

`load_local_bundle(input_manifest_ref, prior_view_path, mode, prior_store)` requires `input_manifest_ref={path,sha256}`. The JSON file refers separately to `prior_universe`, `forecast_candidates`, and `required_market_dependencies` files, each by path and SHA-256. The first is the full registered candidate universe, the second is the subset this run must audit, and the third maps each route/candidate to actual bar dependencies (including peers/QQQ when applicable). These lists cannot silently filter one another; after feature construction the adapter requires `lineage.used_market_symbols` to equal the declared per-candidate dependency set. The input manifest also names a frozen calendar file, symbol bar Parquet/JSON files, symbol corporate-action JSON files, and optionally group versions, memberships, and universe-symbol files. Each file is hashed before and after parsing; content, IDs, session structure, symbols, and forbidden future-label columns are checked. Its `feature_calendar_start` must be explicitly registered when a frozen model used a shorter calendar prefix. The PriorView is verified against the prior-store seal and its actual `observed_through_at` must not exceed the 11:30:30 information deadline.

`run_local_e2e(plan, new_output, fixture_ledger, prior_store)` requires a new output directory and a pre-registered fixture cohort. The plan supplies `mode`, `session_date`, `input_manifest`, `prior_view_path`, `route_manifest`, complete `spec`/`route`/`cohort`, and `run_id`. It saves an immutable plan copy, per-candidate preledger audit, final ledger audit if predictions existed, summary with source/model/data/prior hashes before and after publication plus timings, or fatal record. It rehashes every successfully parsed input reference, route artifact, and sealed PriorView both before and after the ledger call; changed bytes produce a fatal record, and any already committed fixture BUY receives a protocol-violation event rather than disappearing. Feature rejection and model/load failure remain per forecast candidate; neither receives fabricated probabilities. Only a successfully built prediction is submitted to `issue_once`, where a real historical fixture remains `data_unverified`. No rejected candidate is labeled `run_empty`. An absent route artifact is a recorded `model_unavailable` for every affected candidate.

The adapter folds PriorView capture time plus present calendar, universe, candidate, dependency, bar, corporate-action, and group receipts into `lineage.latest_available_at/latest_received_at` before recomputing prediction JSON SHA, so the ledger's actual-publication check sees all known dependencies. Missing receipts remain explicit. File hashes alone never set G2. Grouped routes without complete group source fields or `group_peer_semantics='v9_causal_history_end_v1'` reject; the feature encoder owns the detailed `group_metadata_incompatible` gate and is not bypassed. `load_route` separately checks the grouped model's `group_training_provenance`; this adapter does not invent one for legacy checkpoints. A grouped metadata fixture failing numerical parity remains G1 FAIL. The route action freeze, official calendar source, 1950-RTH-minute horizon, real receipts, and measured 30-second operation are separate report gates; the total status is always fixture-only in this module.

## Validation and limits

`test_local_adapter.py` exercises a real historical AMD 5m Parquet path and real B_no_group checkpoint through feature-only inference to ledger refusal, with two frozen prior-universe members but only AMD in the forecast subset. It also tampers a route manifest to verify every candidate gets `model_unavailable`, and changes a temporary corporate-action file after the ledger call to prove fatal revalidation and before/after hashes. A **separate ledger/labels/evaluate combination test**, outside `run_local_e2e`, uses entirely synthetic fixtures to issue five BUYs, mature nine labels, and obtain `TP=2, FP=1, pending=1, missing=1, N=5` across 60 registered sessions; the unresolved two prevent a pass. The real AMD test is historical G1-path evidence only: its imported PriorView has no rows knowable in June and no then-recorded receipts, so it cannot prove numeric parity or G2. The synthetic BUY test proves denominator handling, not an adapter five-route E2E, live signal, or 90% effect.

Root review found a specific fail-open path: a damaged PriorStore seal/hash chain with unchanged PriorView file bytes was being treated as valid by the post-run fallback SHA check. The fallback now preserves the file SHA **and** records the seal error as a mismatch; strict pre/post revalidation fails and saves fatal evidence. The regression corrupts a `view_created` event after ledger return while leaving the view file untouched, verifies identical file SHA, and requires fatal seal failure. Focused prior-store and adapter checks pass: 11/11.

The registered group-gate follow-up also requires the grouped `universe_symbols` file to equal the **complete** registered candidate set from `prior_universe`. A forecast subset cannot shrink the peer universe; duplicates, extras, missing peers, or a benchmark `QQQ` entry fail before feature construction. The added fixture rewrites all local source and manifest SHA references for each malformed set, so the rejection proves the membership contract rather than a stale-file hash. Direct feature tests separately reject unsupported classified categories and unknown own/peer version references before a classified row can become a zero mask. Each of the five supported strategies keeps its three registered categories; legal future versions, unrelated rows, and explicit `insufficient_history` retain their previous masks. The 10 forward test modules, including calendar checks, pass 58/58 under Python 3.12.13.

# All-candidate mature-prior store · code review

2026-09-27. Scope: `prior_store.py` and fixture tests only. This is the P0/P1 local component from `forward_readiness/INTEGRATION_PLAN.md`; it creates no real cohort, prediction, download, order, or scheduled job.

## Contract

- `register_candidates(universe_version, official_session, eligibility_manifest, store)` freezes one row for every candidate in the complete universe for that session. Benchmark `QQQ` is not a candidate. A missing member, duplicate sample ID, changed manifest, future outcome, score, threshold, or BUY-dependent eligibility fails. Candidate key contains universe version, symbol, session, 11:30 cutoff, and label contract; routes do not create extra candidates. Registration is one SQLite transaction with an append-only event chain.
- `update_candidate_outcomes(candidate_ids, local_outcome_snapshot, calendar, asof, store)` calls the shared pure `evaluate_candidate` for every requested candidate, including those never issued as BUY. It saves all nine target statuses, label windows, source/action/calendar hashes, evaluation time, and `supersedes`; unresolved status is preserved. It never writes the BUY ledger.
- `read_prior_asof(symbols, information_deadline, store_cut, store)` captures the actual clock immediately and selects versions knowable by `observed_through_at = min(information_deadline_at, captured_at)`. This permits a view at 11:30:05 for an 11:30:30 prediction deadline without admitting an 11:30:20 revision into that earlier view. Both timestamps are sealed. Effective `label_available_at` is the maximum of raw label availability, source receipt, action receipt, and outcome event `recorded_at`. Only complete binary nine-label rows enter `PriorView.rows`; every registered candidate remains in coverage counts. The output is an immutable, content-addressed JSON file plus a hash-chain seal. `verify_prior_view` checks both. Selected version IDs and source hashes remain visible.
- `PriorView.rows` is the six-field list accepted by existing `features._prior`: `sample_id`, `symbol`, `decision_at`, `label_end_at`, effective `label_available_at`, `y[9]`. The feature module still owns the last-63 Beta(1,1) calculation. The adapter owner can pass rows without creating another schema or replacing the frozen prior formula.

Fixture mode permits an injected clock and digest-only synthetic sources. `historical_fixture` and `live` use the actual system clock and cannot inject a backdated one. Live registration requires source files and receipt by 11:30:30 plus registration by that deadline. Live outcome updates require local source/action files and receipts no later than current time; a future information deadline does not extend the view beyond its actual capture time. A historical import records its actual import time, so an old as-of deadline cannot treat it as contemporaneous evidence. These checks are local and do not independently authenticate a provider receipt.

## Verification and boundary

`test_prior_store.py` covers complete-manifest rejection, restart/retry idempotence, non-BUY rows, early first touch remaining pending, full-window maturity, late receipt, 11:30:05 capture versus 11:30:20 revision, supersession without changing an old view, 63-row Beta compatibility, future cut, source/view tamper, transaction rollback, and historical clock isolation. The test bars, corporate-action coverage, and synthetic 64-row mathematics case are explicitly fixtures. Their timestamps do not establish real contemporaneous acquisition or a 90% result.

P0/P1 component evidence supports only local G1 engineering checks. Full frozen prior universe/eligibility input manifests, local adapter, actual source/receipt collection, complete official calendar, five-route parity, measured 30-second runtime, and live G2/G3 evidence remain separate integration work. Until those are satisfied, this component cannot authorize a real cohort or publication.

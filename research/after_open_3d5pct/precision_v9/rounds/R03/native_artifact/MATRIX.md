# R03 原生工件方案矩阵

2026-09-27；基于STATE实际缺口，先选有限工程，不将工件导出视为模型效果迭代。

| 方案 | 收益 / 成本与风险 | 决定 |
|---|---|---|
| 拟合前原生合同＋fit后薄导出＋正式load→predict | 直接服务下一30套模型，及时区分旧/新输入语义；新增生产schema函数、导出/验证模块、小登记连接和必要provenance核验 | **选择，根采用后实施**；数据与训练另门禁 |
| 只训练，之后手工拼manifest/provenance | 初期少代码，训练时未冻结的输入/版本/来源可能无法补证 | 不选；不在事后把旧版本改成causal |
| 先给旧模型六键历史兼容证书 | 可补旧接口正向证据，但已完成数值审计；不能服务新日期或完整21候选性能 | 保留未采用草案，暂缓 |
| 写通用registry/证书/部署平台 | 超出当前30工件需要，增加未知依赖和维护成本 | 不做；只文件制品及现有正式接口 |
| 把old_common也改用R03M/new群，或导出时自动refit | 会改变匹配对照、混入另一训练语义，效果变化不可归因 | 拒绝，原三臂与模型配方不变 |

| 验证层 | 能采用的结论 | 不能外推 |
|---|---|---|
| synthetic fixture /已有旧engine接口对照 | 导出合同/哈希/进程隔离及旧数值路径可工作 | 新数据合格、causal新模型已训练 |
| 真实fit后静态tensor load→predict | 该route/arm/fold工件及原eval参考复放成立 | feature-only新前缀同义、未来receipt成立 |
| 冻结代表feature-only→正式接口 | 实际日期/metadata/来源范围内输入/数值契约成立 | 新日期自动授权、全21×5满足30秒 |
| 全21×5同快照计时 | 实际合法范围下总/阶段性能 | 无receipt的fixture变成G2；模型达到90% |

独立接口child的额外进程成本可测量，不能为少启进程更改B loader的已知导入顺序门禁。开发期阈值/评分仍按各路线原baseline；任何反例失败只阻止导出采用，完整拟合证据保留。
